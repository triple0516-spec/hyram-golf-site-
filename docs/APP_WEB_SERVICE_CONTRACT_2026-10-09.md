## 앱/웹 공통 문의 흐름
1. 서비스 선택 → 이름 → 연락 방법/연락처 → 희망 날짜·시간(선택) → 요청사항.
2. 개인정보 수집·이용 동의 전에는 문의를 전송하지 않는다.
3. 백엔드가 연결되지 않은 경우 **접수 완료**로 표시하지 않는다. '접수 내용 확인'과 '카카오톡으로 최종 접수'를 분리한다.
4. 문의 확인 화면은 개인 연락처를 URL 쿼리스트링에 담지 않는다.
5. 실제 예약 가능 여부, 결제 승인, 주문 확정, 재고 확약을 가짜 성공 화면으로 표현하지 않는다.
6. 고객 상담: https://open.kakao.com/o/sFKnP4Qi

## 공통 화면 상태
- READY: UI 접근 가능, 외부 연동 필요 없는 기능
- INQUIRY_ONLY: 문의 초안 작성 가능, 상담사 최종 확인 필요
- BLOCKED: PG/로그인/예약 서버 미연동으로 실제 거래 불가
- NOT_TESTED: Galaxy 실기기 또는 운영 환경 미검증
- PASS: 해당 revision과 환경에서 증거가 확보된 테스트만 표시

## 출시 의존 게이트
Toolchain → Host → pub → analyze → test(internal/production) → Android integration → APK/checksum → Native UI → Galaxy 실기기 QA → 로그인·예약·결제/취소·환불 실연동 → 스토어 등록.
실패하면 즉시 중단, 원인 특정·수정·동일 조건 재검증 후 PASS 증거 확보. BLOCKED와 NOT_TESTED는 PASS가 아니다.

## 구현 우선순위
1. 공통 서비스 ID 및 문의 폼 입력 검증 일치
2. 로그인·회원가입/권한·개인정보 보호와 백엔드 설계
3. 상품/중고/피팅/레슨/부킹 목록과 상세 화면
4. 주문·예약 이력, 고객 응대 상태 관리
5. 테스트 PG 및 실제 예약 공급자 연동 후 취소·환불 검증
6. Galaxy QA, 웹 접근성·모바일 QA, 최종 배포
